## 1. Authority and scope

This document is the required design entry before a migration. It is **not** the physical source of truth after a migration is applied: the immutable Alembic migration and schema snapshot then become physical authority. Drift between migration, this dictionary and contract registry blocks deployment.

Only the Task 0.3 `platform` delivery baseline has complete column-level proposed entries below. It is intentionally DRAFT and authorizes no migration. Other v1 tables are an inventory only until a phase/task/ADR needs them.

## 2. Dictionary conventions

| Rule | Convention |
|---|---|
| PK | internal `UUID` containing application-generated UUIDv7; no UUIDv4 default/generator |
| Time | `TIMESTAMPTZ` UTC; semantic field names only; application supplies event/domain time, database/approved write path records persistence time |
| Decimal | all financial values `NUMERIC(38,18)` and no float; Task 0.3 platform tables have no financial column |
| Status | `TEXT` guarded by explicit `CHECK`; a new status is a contract/migration change |
| JSONB | only versioned wire payload/redacted extension metadata; not financial/lifecycle core state |
| Hash | `CHAR(64)` lowercase SHA-256 hex of canonical JSON/approved bytes, validated by CHECK |
| Retention | no hard delete for financial/audit/event evidence; platform purge only after ADR-0013 policy and replay/dedupe window |
| Foreign key | allowed only in same schema/context; `ON DELETE CASCADE` is forbidden for history/evidence tables |
| Access | runtime uses context role; `db_migrator` alone runs DDL |

All exact default values below are proposed physical contract. Any change requires a dictionary change, migration/change plan and task/ADR review.

## 3. Task 0.3 physical table: `platform.outbox`

| Attribute | Value |
|---|---|
| Context/schema owner | `platform` / `platform` |
| Purpose | immutable committed integration event awaiting or having undergone delivery |
| Classification | operational confidential; payload classification inherits event contract and must be redacted before DLQ/log copies |
| Writer | owner application transaction through platform port; no publisher UPDATE |
| Readers | outbox publisher, audited operations reader; no dashboard direct DB |
| Retention | retain until approved archive/purge policy; no runtime `UPDATE`/`DELETE` |
| Query/index need | look up by `event_id`, source subject/correlation audit; delivery scan uses delivery-state table |

| Column | PostgreSQL type | Null | Default | Validation / semantics |
|---|---|---:|---|---|
| `outbox_id` | `UUID` | no | none | PK; UUIDv7 generated by application |
| `event_id` | `UUID` | no | none | unique canonical event envelope ID; no cross-context FK |
| `source_context` | `TEXT` | no | none | CHECK one of approved bounded-context names; identifies producing owner |
| `source_aggregate_type` | `TEXT` | no | none | stable canonical aggregate type, not ORM class name |
| `source_aggregate_id` | `UUID` | no | none | source/subject ID; trace reference only, no cross-context FK |
| `event_type` | `TEXT` | no | none | past-tense, versioned event name such as `<context>.<event>.v1` |
| `schema_version` | `SMALLINT` | no | none | CHECK `schema_version > 0` |
| `partition_key` | `TEXT` | no | none | ordered delivery scope; order lifecycle uses canonical `order_id` text |
| `payload` | `JSONB` | no | none | validated against registered event schema before insert; no secret/raw credential |
| `payload_hash` | `CHAR(64)` | no | none | lowercase SHA-256 CHECK; hash of canonical payload bytes |
| `occurred_at` | `TIMESTAMPTZ` | no | none | event/domain occurrence UTC |
| `recorded_at` | `TIMESTAMPTZ` | no | none | durable record UTC; must be >= `occurred_at` unless documented source clock skew evidence |
| `correlation_id` | `UUID` | yes | none | end-to-end correlation UUIDv7 when internal |
| `causation_id` | `UUID` | yes | none | direct prior event/command ID when available |
| `trace_id` | `TEXT` | yes | none | trace context identifier; must be log-safe and no secret |

Constraints/indexes proposed:

- `PRIMARY KEY (outbox_id)`; `UNIQUE (event_id)`.
- CHECK `payload_hash` matches `^[0-9a-f]{64}$`; CHECK `event_type` and `partition_key` are non-empty; CHECK `recorded_at >= occurred_at` except a separately approved documented clock-skew handling path.
- Index `outbox_event_id_uq` is implicit from unique; add non-unique audit index on `(source_context, source_aggregate_id, recorded_at)` only if query budget confirms it.
- Row is append-only: runtime publisher does not mutate it. Delivery state lives in `platform.outbox_delivery_state`.

## 4. Task 0.3 physical table: `platform.outbox_delivery_state`

| Attribute | Value |
|---|---|
| Context/schema owner | `platform` / `platform` |
| Purpose | mutable technical lease/retry state for one immutable outbox message |
| Classification | operational confidential |
| Writer | publisher worker through platform port |
| Readers | publisher/operations diagnostics |
| Retention | retained with corresponding outbox record; never treated as business/audit truth |
| Query/index need | claim due rows via `status`, `next_attempt_at`; investigate lease/outcome |

| Column | PostgreSQL type | Null | Default | Validation / semantics |
|---|---|---:|---|---|
| `outbox_id` | `UUID` | no | none | PK and same-schema FK to `platform.outbox(outbox_id)` with `ON DELETE RESTRICT` |
| `status` | `TEXT` | no | `'PENDING'` | CHECK `PENDING`, `CLAIMED`, `PUBLISHED`, `DEAD_LETTER` only |
| `attempt_count` | `INTEGER` | no | `0` | CHECK `attempt_count >= 0`; increments once per actual publish attempt |
| `next_attempt_at` | `TIMESTAMPTZ` | no | none | due time for a bounded retry; initial value is created transaction time |
| `claim_owner` | `TEXT` | yes | none | machine identity, never credential/token |
| `claim_fencing_token` | `BIGINT` | yes | none | CHECK positive when non-null; protects internal state write |
| `claim_expires_at` | `TIMESTAMPTZ` | yes | none | lease expiry; not proof an external request did not happen |
| `last_attempt_at` | `TIMESTAMPTZ` | yes | none | actual external/in-process publish attempt time |
| `published_at` | `TIMESTAMPTZ` | yes | none | confirmed publisher completion time, not consumer completion |
| `last_error_code` | `TEXT` | yes | none | registered/redacted failure category only |
| `last_error_hash` | `CHAR(64)` | yes | none | hash of redacted error/evidence when present |
| `delivery_version` | `BIGINT` | no | `0` | CHECK `delivery_version >= 0`; compare-and-swap version |
| `updated_at` | `TIMESTAMPTZ` | no | none | time of last state change |

Constraints/indexes proposed:

- State checks: `PUBLISHED` requires `published_at`; `CLAIMED` requires `claim_owner`, `claim_fencing_token`, `claim_expires_at`; `PENDING`/`PUBLISHED` must not hold active claim fields; `DEAD_LETTER` requires `last_error_code`.
- `FOREIGN KEY (outbox_id)` references `platform.outbox` with `ON DELETE RESTRICT`; no cascade.
- Partial claim index: `(next_attempt_at, outbox_id)` WHERE `status IN ('PENDING','CLAIMED')`; operational diagnostic index `(claim_owner, claim_expires_at)` WHERE `status = 'CLAIMED'`.
- Update requires `delivery_version` compare-and-swap and transaction/lease rules in [transaction and concurrency](transaction-and-concurrency.md). This table is the documented mutable exception; it contains no financial/domain truth.

## 5. Task 0.3 physical table: `platform.inbox`

| Attribute | Value |
|---|---|
| Context/schema owner | `platform` / `platform` |
| Purpose | immutable idempotent consumer receipt written atomically with successful consumer-side effect |
| Classification | operational confidential |
| Writer | named consumer transaction through platform port |
| Readers | consumer recovery/operations diagnostics |
| Retention | at least approved dedupe/replay window; final policy requires ADR-0013 |
| Query/index need | duplicate lookup by consumer/event, audit by correlation/processed time |

| Column | PostgreSQL type | Null | Default | Validation / semantics |
|---|---|---:|---|---|
| `inbox_id` | `UUID` | no | none | PK; application-generated UUIDv7 |
| `consumer_id` | `TEXT` | no | none | stable logical consumer name; not ephemeral process ID |
| `event_id` | `UUID` | no | none | canonical source event ID; no required FK because event may be external/replayed |
| `event_type` | `TEXT` | no | none | event contract name received |
| `schema_version` | `SMALLINT` | no | none | CHECK `schema_version > 0` |
| `partition_key` | `TEXT` | no | none | source event ordering scope |
| `source_context` | `TEXT` | no | none | declared producer context |
| `result_hash` | `CHAR(64)` | no | none | canonical hash of committed result/effect reference; never raw secret |
| `processed_at` | `TIMESTAMPTZ` | no | none | consumer effect/receipt commit time UTC |
| `recorded_at` | `TIMESTAMPTZ` | no | none | persistence time UTC; normally same or later than `processed_at` |
| `correlation_id` | `UUID` | yes | none | trace correlation when supplied |

Constraints/indexes proposed:

- `PRIMARY KEY (inbox_id)` and `UNIQUE (consumer_id, event_id)`.
- CHECK non-empty `consumer_id`, `event_type`, `partition_key`, `source_context`; SHA-256 regex on `result_hash`; `recorded_at >= processed_at` except documented clock-skew path.
- Index `(consumer_id, processed_at DESC)` for recovery/audit and `(correlation_id, processed_at DESC)` where correlation query budget approves it.
- Row is inserted only in the same transaction as the consumer’s successful local effect/outbox write. A failed handler creates no success receipt; retry must be safe. No runtime update/delete.

## 6. Task 0.3 physical table: `platform.dead_letters`

| Attribute | Value |
|---|---|
| Context/schema owner | `platform` / `platform` |
| Purpose | immutable redacted evidence of terminal/bounded-retry delivery failure |
| Classification | operational confidential; must contain no raw secret/unredacted payload |
| Writer | platform publisher/consumer failure handler |
| Readers | authorized operations/reconciliation diagnostics |
| Retention | subject to approved evidence/replay policy; no runtime delete |
| Query/index need | investigate by outbox/event/consumer/correlation/failure time |

| Column | PostgreSQL type | Null | Default | Validation / semantics |
|---|---|---:|---|---|
| `dead_letter_id` | `UUID` | no | none | PK; UUIDv7 |
| `outbox_id` | `UUID` | yes | none | same-schema FK when failure originated from local outbox; null for external consumer source |
| `consumer_id` | `TEXT` | yes | none | required when `failure_stage = 'CONSUME'` |
| `event_id` | `UUID` | no | none | event identity |
| `event_type` | `TEXT` | no | none | versioned event name |
| `failure_stage` | `TEXT` | no | none | CHECK `PUBLISH` or `CONSUME` |
| `failure_code` | `TEXT` | no | none | stable machine-readable redacted error code |
| `failure_detail_redacted` | `TEXT` | yes | none | operator-safe diagnostic; must not include raw credential/payload |
| `payload_hash` | `CHAR(64)` | no | none | hash/reference only, not duplicate raw payload |
| `attempt_count` | `INTEGER` | no | none | CHECK `attempt_count > 0` |
| `first_failed_at` | `TIMESTAMPTZ` | no | none | first known failure time |
| `recorded_at` | `TIMESTAMPTZ` | no | none | durable evidence time UTC |
| `correlation_id` | `UUID` | yes | none | link to tracing/audit context |

Constraints/indexes proposed:

- `PRIMARY KEY (dead_letter_id)`; `FOREIGN KEY (outbox_id)` with `ON DELETE RESTRICT` when non-null.
- CHECK `recorded_at >= first_failed_at`, non-empty `failure_code`/`event_type`, SHA-256 format and consumer requirement for consume stage.
- Index `(event_id, recorded_at DESC)`, `(outbox_id, recorded_at DESC)` where non-null, and `(failure_stage, recorded_at DESC)` for alert/runbook queries.
- A resolution is recorded by a separate audited command/event, not by erasing or overwriting this evidence row.

### 7.1 Phase 6 AI/BYOK deferred-table policy

The following are logical targets only. They are **not** DDL authorization and must not be created before a Phase 6 task has an approved dictionary entry, contract, migration plan and gate evidence.

| Logical table | Context owner | Purpose / permitted metadata | Explicit prohibition |
|---|---|---|---|
| `operations.ai_provider_connections` | operations | opaque connection ID, owner scope, environment, provider/model/catalog/adapter artifact version, resolved policy-profile/endpoint/egress/usage IDs, internal active/candidate binding IDs, status/revision, safe timestamps | raw API key, encrypted key blob, authorization header, public `secret_ref` or vendor raw response |
| `operations.ai_connection_events` | operations | append-only create/enroll/validate/activate/suspend/rotate/expire/revoke audit metadata, actor/reason/correlation and normalized result | secret enrollment body, raw key, key fingerprint/length/body hash or raw provider error |
| `ai_memory.inference_runs` | ai_memory | connection revision, provider/model/profile/prompt-policy/schema version, sanitized input hash/classification, timing, usage/cost and normalized status | raw credential, raw prompt/response by default, execution/risk/config action |
| `ai_memory.proposals` / `memory_items` | ai_memory | validated structured content, provenance/review/retention/point-in-time fields under policy | automatic live promotion, secret, unreviewed instruction or future-memory replay leakage |

Internal active/candidate binding IDs are opaque metadata only. The binding-to-secret mapping remains inside the approved secret provider boundary and is never a column exposed through dashboard, public API, event or evidence. A schema fixture may use a synthetic opaque UUID solely to validate lifecycle shape; it is not a secret reference and cannot resolve to a real vault object. Owner scope is single Account Owner/account environment in the current MVP; a future tenant/workspace field requires a separate approved scope/authorization design.

## 8. Mandatory dictionary fields for future tables

Each future entry must provide: schema/context owner; purpose/classification/retention; writer/reader roles; primary/business key; each column type/null/default/semantics; enum/CHECK/unique/FK scope; append-only/mutable and aggregate version; timestamps; query/index budget; linked requirement/ADR/contract/migration; backfill/forward-fix plan; fixture/constraint/property/integration test reference.

## 9. Approval checklist for Task 0.3

- [ ] ADR-0003, ADR-0004 and ADR-0012 are APPROVED.
- [ ] Exact delivery lifecycle/lease/retry values are approved or represented as validated configuration, not hidden defaults.
- [ ] Migration plan creates only tables in §§3–6 and no unapproved schema/table/index.
- [ ] Role grants protect immutable rows; test plan proves uniqueness, CAS/lease, crash retry and no payload/secret leak.
- [ ] Dictionary, ERD, contract registry and task card links are reviewed by required roles.
